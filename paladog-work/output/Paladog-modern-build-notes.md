개인용 수정본이며 공식 개발사 배포본이 아니다. 바이러스가 있었다거나 모든 위험이 제거됐다고 단정하는 결과도 아니다. 첨부 분석의 주장은 실제 파일과 대조했으며, 다른 배포 사이트의 APK 전체를 이번 환경에서 비교한 것은 아니다.

## 개인정보·온라인 기능 변경

- 시작 시 전화번호·IMEI 조회를 제거했다. 저장용 기기 ID는 원래 게임이 지원하는 빈 문자열 경로를 사용한다. Android ID 조회도 비개인 고정 문자열로 대체했다.
- SMS 마케팅과 Naver 동의 화면 및 등록 요청을 제거했다. 재실행 시 전투 복원 확인창은 유지했다.
- 게임 홍보 배너와 What's New 버튼, 외부 사이트·소셜 버튼을 숨기고 관련 진입을 차단했다.
- GCM 등록과 푸시 수신 컴포넌트, 결제 서비스 연결, 원격 치트 목록과 실행 프로세스 조회를 제거·비활성화했다.
- 공용 HTTP 함수와 서버 세이브 업로드·다운로드를 비활성화했다. 외부 브라우저 등에 위임하는 Activity 실행도 차단했다.
- APK Manifest에 명시된 권한은 `VIBRATE`만 남겼다. 인터넷·전화·계정·외부 저장소 권한은 없으며 자동 백업과 외부 컴포넌트 노출도 제한했다.
- 서바이벌은 원래의 해금 조건을 거쳐 기존 오프라인 경로로 연결한다. 로컬 랭킹과 업적은 보존한다. 온라인 랭킹·로그인·결제 서비스는 작동하지 않는다. 결제 버튼은 구매 성공을 만들지 않고 로컬 안내로 끝난다.

게임 밸런스, 골드, 콘텐츠 해금 조건을 바꾸지 않았다. 원본의 라이선스 정책은 이미 항상 허용을 반환했으며, 이번 수정으로 새로 변경하지 않았다. 이 정책과 게임 초기화 콜백은 그대로 유지한다.

## 64비트 전용 기기를 위한 변경

전투 엔진·렌더러·세이브는 Java/DEX 코드였다. 네이티브 메서드 327개와 라이브러리 로딩 지점 3개는 외부 SDK에만 있었다. 남은 게임 코드에서의 참조와 클래스 이름 문자열을 확인한 뒤 AppleJuice·ApplePay·Kakao·Tenpay/OICQ 및 미사용 `TestAJService` 총 928개 클래스를 제거했다.

ARM 32비트 `.so` 네 개도 제거했다. 최종 APK에는 네이티브 메서드, 라이브러리 로딩 호출, ELF 파일이 없다. 이 방식은 ARM32 기계어를 ARM64로 변환한 것이 아니라, Android의 64비트 Java 런타임에서도 실행할 수 있는 구성을 만든 것이다. 앱 자체 네이티브 라이브러리가 없어 해당 라이브러리의 16KB 페이지 크기 대응 문제도 없다.

target SDK 28은 최신 Android의 낮은 target 설치 제한을 넘으면서 구형 화면 엔진의 동작을 유지하기 위한 선택이다. Play Store 신규 등록 기준을 충족하는 배포 프로젝트를 만든 것은 아니다. target 35 이상에서 강제되는 edge-to-edge에는 이 게임에 없는 화면 인셋 처리가 필요하므로, 숫자만 최신으로 올리지 않았다.

가로 화면을 유지하고 화면 크기·레이아웃 변경을 Activity에서 처리하도록 선언했다. 임의 다중 창 크기 변경을 제한했으며, 남아 있는 라이선스 코드의 Apache HTTP 클래스 참조를 위해 `org.apache.http.legacy`를 선택적 라이브러리로 선언했다. 제조사별 화면 처리까지 이 설정만으로 보장하지는 않는다.

## 최신 폰트의 글자 잘림 수정

실행 시험에서 종료 안내문의 일부 줄이 잘리는 문제를 발견했다. 구형 Cocos2d가 문자열 전체를 측정해 한 줄 높이의 이미지를 만든 뒤, 다시 단어별 너비 합계로 줄을 나누면서 현대 Android 폰트의 간격 차이에 따라 불필요한 두 번째 줄을 만드는 문제였다.

`CCTexture2D.WrapText()`에 문자열 전체가 주어진 너비에 들어가면 한 줄로 그대로 반환하는 처리를 추가했다. 너비를 넘는 문장은 원래 줄바꿈을 사용하며, 나머지 렌더링 메서드·게임·저장 코드는 변경하지 않았다. 화면 비율을 제한하거나 안내문 내용을 삭제하는 방식은 사용하지 않았다.

## 저장과 기존 설치

현재 세이브는 앱 내부 `shared_prefs/PDWXMLInfo.xml`, `PDWXMLSlot0..7.xml`, `PDWXMLBattle.xml` 등에 기록된다. `files/*.sav`는 구형 저장의 읽기 경로다. 저장 구조체·암호화·게임 저장 구현은 원본 그대로 보존했다. 빈 ID 경로는 현재 ID와 과거 기록의 불일치 표시를 해제하는 원래 로직을 이용한다.

새 개인용 서명으로 만들었으므로, 다른 서명을 가진 기존 앱 위에 일반 업데이트로 설치할 수 없다. **기존 진행 데이터가 있다면 먼저 백업을 확보하고, 백업 확인 없이 기존 앱을 삭제하지 말 것.** 사용자의 실제 과거 세이브 이전은 검증하지 않았다. 이번 작업의 이전 개인정보 보호 빌드와는 같은 개인키를 사용한다.

## 정적 검증

- APK 서명 v1/v2/v3 및 ZIP 정렬 검증 통과.
- 다시 분해한 APK에서 권한, Manifest, 삭제 클래스, 네이티브 의존성 부재를 검사했다.
- 남은 클래스 1,176개 중 1,175개는 개인정보 보호 패치 이후의 코드와 동일하다. 나머지 `CCTexture2D`에는 아래의 글자 표시 수정만 추가했다. 재조립 과정의 라벨 이름·디버그 정보 차이를 제외하고 명령·레지스터·분기 대상을 비교했으며, 원래 줄바꿈 처리와 나머지 메서드가 보존됐는지도 확인했다.
- 원본과 비교해 Manifest와 DEX를 변경하고 `.so` 네 개를 제거했다. 나머지 4,763개 파일은 바이트 단위로 동일하다. 게임 이미지·사운드·DB·리소스 테이블이 포함된다.
- 검증 스크립트의 성공 항목에는 클래스별 반복 비교가 포함된다. 이를 독립적인 보안 시험 수로 해석하지 않는다.

## 실행 검증

글자 표시 수정 전 후보의 SHA-256은 `44d1885f7a37bc38acd895a6a793924afc239f3cd56ad3f09f57e697ad55d5c2`다. 아래의 두 기존 실행 보고서는 이 후보의 기록이며, 최종 파일의 글자 수정 회귀 시험과 구분한다. 두 빌드의 게임·저장 코드와 리소스는 동일하다.

이 후보를 설치한 파일의 해시를 다시 확인하고, 개인 계정·자료가 없는 Android 6/API 23 ARM32 에뮬레이터에서 다음을 확인했다.

- 메인 메뉴에서 What's New가 사라짐.
- 서바이벌 진입 시 로그인 선택 없이 기존 오프라인 경로로 진행.
- 상점·장비 화면, 실제 전투와 유닛 소환 동작.
- 게임 종료 확인창의 정상 종료로 저장한 뒤 앱 프로세스 종료 확인.
- 재실행 시 전투 복원 안내를 선택해 실제 전투로 복귀하고 일시 정지.
- 해당 시험 로그에서 치명적 Java 예외, 클래스 누락, 네이티브 라이브러리 누락 오류가 발견되지 않음.

이 시험은 `evidence/runtime/final-api23/RESULT.md`와 화면 기록에 정리했다. 앱의 IPv4·IPv6 외부 통신을 게스트 방화벽으로 차단한 상태에서 수행했다. `evidence/runtime/legacy-runtime-validation.json`의 이전 후보 APK 시험과 구분한다.

Android 16/API 36 AOSP **64비트 전용 x86_64 에뮬레이터에서도 같은 후보 APK 실행 검증을 통과했다.** 설치 제한을 우회하지 않고 일반 설치했으며, 설치된 APK를 읽어 후보 해시와 일치함을 확인했다. `app_process64`, `zygote64`, 빈 32비트 ABI 목록과 64비트 라이브러리 매핑으로 실제 64비트 실행을 확인했다.

- 새 설치의 메인 메뉴가 표시됐고 What's New 버튼이 없었다.
- 이 작업에서 만든 Android 6의 테스트 세이브 11개를 바이트 변경 없이 옮겼다. 실제 사용자 세이브는 사용하지 않았으며, 해금 조건이나 저장 값을 편집하지 않았다.
- 옮긴 세이브에서 실제 전투로 복귀하고 터치로 유닛을 소환했다.
- Android 뒤로 가기로 게임의 종료·저장 확인창을 열어 정상 종료했다. 프로세스 종료를 확인한 뒤 64비트 환경에서 새로 기록된 세이브 11개를 보존했다.
- 다시 실행해 새 세이브의 이어하기 안내를 선택하고, 유닛과 적이 있는 실제 전투로 복원되는 것을 확인했다. 결과와 화면은 `evidence/runtime/final-api36/RESULT.md`에 있다.

**최종 글자 수정본 `c8211db6…`도 별도로 다시 시험했다.**

- Android 6: 같은 키로 업데이트한 뒤 세이브 XML 11개의 바이트가 그대로 유지됐음을 확인했다. 설치 파일 해시를 재확인하고 기존 전투 복원, 입력 반응 및 잘리지 않는 종료 안내문을 확인했다. 앞선 후보의 전체 저장 시험과 이 최종본의 회귀 시험을 구분한다.
- Android 16 64비트 전용 환경: 같은 키로 업데이트하고 기존 저장을 복원했다. 이전에 잘렸던 종료 안내문이 모두 표시되는 것을 실제 화면에서 확인했다. 최종본으로 정상 저장·프로세스 종료·재실행을 거쳐 다시 실제 전투로 복원하는 과정도 통과했다.

최종 회귀 시험 기록은 `evidence/runtime/final-api23-textfix/RESULT.md`, `evidence/runtime/final-api36-textfix/RESULT.md`다. [수정된 종료 안내문](../evidence/runtime/final-api36-textfix/03-quit-text-fixed.png)과 [최종본의 저장 복원 화면](../evidence/runtime/final-api36-textfix/07-restored-live-combat.png)을 함께 제공한다.

두 환경 모두 게스트 IPv4·IPv6 통신을 차단했다. Android 16에서는 SELinux Enforcing도 유지했다. 이 클라우드 호스트에는 KVM이 없어 소프트웨어 에뮬레이션이 느렸다. 테스트 게스트의 정상 userdebug 권한으로 Android의 느린 하드웨어용 시간 제한 배수를 10으로 설정해 시스템 시작 오류를 해결했다. APK를 바꾼 설정이나 실제 휴대폰에 요구되는 설정은 아니며, 이 환경의 실행 속도로 실기기 성능을 판단할 수 없다.

**Galaxy S26·ARM64·Samsung One UI 실기기는 시험하지 않았다.** 위 결과는 32비트 라이브러리 의존성을 제거한 APK가 실제 64비트 Android 런타임에서 동작한다는 근거이며, 특정 휴대폰의 GPU·화면·소리·성능까지 보증하지 않는다. 모든 캠페인 스테이지, 다크독 진행, 모든 아이템·업그레이드와 소리는 전수 검증하지 않았다.

Android 16의 패키지 관리자에는 구형 target 호환 처리로 `POST_NOTIFICATIONS`도 추가돼 표시되지만, 시험 환경에서 허용 상태는 `false`였다. APK Manifest가 이 권한을 선언한 것은 아니며, `INTERNET`은 설치 후에도 없었다.

## 재현 자료

`REPRODUCE.md`에 원본 분해부터 개인정보 패치, 최신 호환 변형, 재빌드·서명·검증 순서를 기록했다. 공개 재현 묶음에는 원본 APK와 개인키·비밀번호를 넣지 않는다. 같은 서명으로 후속 업데이트하려면 로컬 `private/` 디렉터리를 별도로 안전하게 보관해야 한다.
